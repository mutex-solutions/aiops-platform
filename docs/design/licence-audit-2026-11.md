## 1. Answer in short

1. **No software base must be rebuilt from scratch because of its licence.** HolmesGPT (Apache-2.0) and GoAlert (Apache-2.0) are both suitable as optional plugins, and the first-party harness and on-call provider of this round are built new by design choice, not by licence need.
2. **What must be built first-party is content:** the compliance control catalogue, its wording and its framework mappings. CIS, SOC 2 and ISO/IEC 27001 text cannot ship in any edition, and the scanners carry text derived from it, in their framework files and also in controls and checks filed under their own ids.
3. **Four packaging items are replaced by templates of our own or by a different engine:** the upstream chart of the profiles store (AGPL-3.0-only), the upstream chart of the metrics store as a packaged sub-chart (its archive embeds an AGPL MinIO chart), Terraform (BUSL-1.1, use OpenTofu), and dashboard-server plugins as items of our index or marketplace (the vendor's plugin policy forbids a separate catalogue).
4. **Fourteen things may exist only as optional plugins or as something the user installs** (section 4). The one that touches the plan most is the Slack platform: its API terms restrict commercial distribution, so the chat-ops bundle is operator-enabled and no release gate depends on it.
5. **The largest risks are contracts, marks and one patent family, not copyleft:** the dashboard vendor's trademark and plugin-signing terms, Slack's and PagerDuty's developer terms, and PagerDuty's schedule patents for a native on-call plugin.

The five uses every licence must allow: **U1** the Apache-2.0 community edition (repository, binary, images, chart, compose file) that bundles or pulls the upstream; **U2** our hosted multi-tenant service running it unmodified; **U3** a later commercial enterprise edition on the same core, with closed plugins in the same binary or as separate processes; **U4** third parties selling plugins that wrap or call it; **U5** its name in a plugin id or description.

| Mode | Meaning | What it triggers |
|---|---|---|
| network | We or the customer call a service somebody runs | Service terms only |
| pull | A chart or compose file of ours names the upstream image by digest; the user's machine pulls it from upstream | We ship the upstream licence text beside the chart and nothing else |
| ship | An image, mirror or offline bundle of ours contains it | Every notice and source duty of every layer in it |
| link | Compiled into our binary or imported by our package | Ship, plus the licence must be on the allow-list of section 7.1 |
| copy, port | Upstream files, text or a close translation sit in our repository | Attribution, licence text, a note of changes |

Verdicts: `ok`, `ok-with-conditions`, `optional-plugin-only` (never in the core, a shipped profile or a release gate), `replace-or-rebuild`, `unverified` (blocks a release that ships it).

## 5. Ok with conditions: the conditions as rules we follow

1. **Pull, do not ship.** Charts and compose files reference upstream images by digest. We publish no mirror and no offline bundle. For air-gapped sites we ship a script that copies the pinned digests from upstream into the site's registry, so the operator copies for its own use and we convey nothing.
2. **Notices travel.** `NOTICE` and `THIRD_PARTY_LICENSES/` carry: both MIT lines of the kernel port; one source line per MPL-2.0 module with its exact version; the Apache-2.0 text and source line for every packaged and nested chart; the ATT&CK and CVE designations; attribution for any copied tool list, cassette, rule or dashboard.
3. **Unmodified.** River, the AGPL servers, the agent and every pulled image run as upstream built them. A patch to an AGPL service lives in a separate AGPL repository; a patched MPL-2.0 file is published. The release keeps an archive of the exact source of every linked MPL-2.0 module (River and its sub-modules, go-plugin, yamux), and any bundle we ever publish carries it.
4. **Release checks, not review:** the lock-file and SBOM check on the pinned HolmesGPT tag; no MinIO image, sub-chart or chart directory; no enterprise image, licence key or flag, with the SeaweedFS ones by name (2.1); nested chart enumeration; the provenance test of the control catalogue (7.4); the register check of section 7.2.
5. **Elections are recorded:** BSD-2-Clause for the sensor's dual-licensed BPF tree (the election does not reach the GPL-2.0-only files in it), Apache-2.0 for osquery and ntfy, MIT for the Falco driver.
6. **Models.** The lab default and any hosted default use Apache-2.0 or MIT weights at a pinned revision, fetched from the publisher.
7. **Default engine.** A plugin that drives an infrastructure-as-code engine works fully with OpenTofu. Terraform is never required for a plugin to operate, and a paid or hosted plugin does not start it before Q17 is answered.

### 7.2 The upstream register

`tools/upstream-components.yaml` (the file 08 §5.1 L3 already names) holds one entry per upstream and per content source: role id, names, form (process, library, service, content, contract, port), the definition it sits behind, plugins, bundle, modules, images, pin, licence, verdict, mode (network, pull, ship, link, copy), per-use blockers, conditions, evidence (URL, date read, version or commit), mark (`suffix-ok`, `needs-approval`, `never`), `contains` for nested charts and image layers, and `default`. The release check fails when a deployed image, linked module, packaged chart, nested chart, baked-in tool or shipped content directory has no entry; when an entry is `unverified`; when an entry with `default: true` is not `ok` or `ok-with-conditions`; when a `replace-or-rebuild` entry appears in any `dist/*.yaml`; when an AGPL entry has modules; when a `ship` entry has no SBOM and source route.

### 7.3 AGPL services, images and bundles

1. The five AGPL servers run unmodified as separate processes from OSS images by digest. We render their configuration and never link their AGPL packages; only the Apache-2.0 sub-trees pinned to the tag in `go.mod` may be imported, and the deny on `pyroscope/api` stays until Q11.
2. Section 13 of the AGPL reaches modified versions only. Hosted adds no plugin, patch or build flag to those images.
3. If a mirror or bundle is ever published, each image in it needs an SBOM and complete corresponding source, or a valid written offer, for every GPL, LGPL and AGPL package in its layers, by delivery form: a pointer to a network server only for a download (AGPL-3.0 and GPL-3.0 §6(d)), source on the medium or a three-year written offer for physical media (§6(a), §6(b)), and GPL-2.0 §3(a) or §3(b) for GPL-2.0 parts. Rule 1 of section 5 avoids all of it.
4. No chart archive we publish contains an AGPL chart.

### 7.4 Content

1. Content ships only when its register entry is `ok` or `ok-with-conditions`. A source annotation is not a licence.
2. No CIS, SOC 2, ISO or PCI text, title or labelled score, in rules, dashboards, personas, tool descriptions, context blocks, skills, cassettes, fixtures or evaluation case files. The release check fails on a content directory or fixture that matches `cis-*`, `*-cis-*`, `soc2`, `iso27001_*`, `pci_*` or `ism`; the second pattern is the form of the Trivy and Trivy Operator compliance specs.
3. The control evaluator applies a display allow-list to scanner results before they reach a screen, a first message or an answer. The list works per control id and provenance, not per framework or scanner. On it: scanner controls and checks that carry no third-party reference, ATT&CK with its notice, our own catalogue. Off it: any control or check whose references point at a restricted source, whatever framework reported it. Today that is cisecurity.org: about 132 Kubescape controls from roughly `C-0092` upward, Trivy checks such as `KCV-0048`, and results of a `cis` compliance spec. A scanner's own frameworks (`allcontrols`, `clusterscan`) are not automatically clean. For anything off the list the evaluator shows our catalogue entry and the scanner's rule id, and no name, description or remediation text. The catalogue build applies the same provenance filter, and a test fails when an entry is taken from a control that carries a third-party reference.
4. Vulnerability and end-of-life data keep their source licence; a cached OSV copy is filtered by source.
5. A pack always carries a digest of a recorded tool list. It carries the recorded text only when the server's licence is on the allow-list, with an attribution line and the licence text; otherwise the publisher writes descriptions in its own words, and `plugin check` and the index lint refuse recorded text from a server with no open licence.
6. Do not restate content from AGPL documentation, commercial products' documentation or unpublished sources. First-party content must follow the accepted requirements and the open publication-rights gate of 08 §5.1 L14; editorial sanitation under ADR-056 is not a claim of independent authorship or rights clearance.

### 7.5 Names and marks

1. The default stack's marks never appear in a product, repository, plugin, row, bundle, profile, container, chart key, metric or config name, in full, abbreviated or combined (00 §8.1).
2. Every other upstream's name appears at most once, as the lowercase suffix of the plugin that wraps it and of that plugin's own bundle, and only when its register entry says `suffix-ok`. An owner whose policy asks for approval (Mattermost, ntfy, PagerDuty, Twilio, PostgreSQL for product names) is `needs-approval`: the id stays generic until cleared. An entry with no policy read defaults to `needs-approval`; that holds for OpenTofu, Tetragon and Pyrra, which are not on the Linux Foundation mark list and whose own pages are unread. For a mark that is on that list (Kubescape, Kyverno, Falco, OpenCost, Argo, Flux, Backstage, KEDA, Chaos Mesh, osquery, Cilium, Atlantis, Prometheus) the usage page allows the title form of rule 3 and says a mark should not be combined, hyphenated or abbreviated, so a hyphenated id that embeds one is not expressly allowed: the entry is `suffix-ok` only after Q4. k6 is `needs-approval` and stricter than the rest: its vendor's policy forbids a mark in a product or service name, has no carve-out for naming a plugin after a tool, and lists the logo as a registered mark. Until a lawyer confirms nominative use or the vendor grants a licence, no id, title or listing of ours or of a seller carries the name or the logo, the tool is named in description text only, and a listing does not print the vendor's attribution sentence, which asserts a permission.
3. Titles read "<own name> <noun> for <System>". An id is never shown as a listing title. No logo, no "official", "certified" or "compliant".
4. The first-party harness, the built-in on-call provider and the SDK are named after no upstream.
5. The index renames an entry on a credible objection from a mark owner (`renamedTo`).
