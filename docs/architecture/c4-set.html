Architecture drawing set · design phase · 2026-11-12

aiops-platform C4 set

An Apache-2.0 AIOps platform on the Grafana observability stack, on-prem and open-source first. One collector-based agent per host or cluster writes four signals through a tenant gateway into the metrics, logs, traces and profiles stores. A small Go kernel runs plugins that turn alerts into incidents, drive a first-party agent harness with a code-driven troubleshooting method, page people and run approved changes. Every upstream is a plugin, never the product.

Read this first

A small kernel, everything else a plugin

Kernel

A Go port of the Cordis model that DeepSeek Harness runs on: a context tree, typed service keys, plugins that start when the services they inject exist and restart in place when a provider is swapped, effects that unwind in reverse, and hooks. It holds no product logic.

Plugins

Everything else is a plugin behind a service definition: sql, jobs, events, http, tenancy, approval, audit, the change ledger, the LLM gateway, fleet, the loader and the plugin manager. Each definition ships a fake and a conformance suite, so a plugin is tested alone before it is attached.

Product

Plugins turn alerts into incidents and run each pillar agent through one neutral harness registry. The default harness and its read tools are first-party and new; HolmesGPT is one optional harness plugin a user can pick per agent. On-call goes through provider plugins, GoAlert being one optional provider.

  • Goal: an open-source community edition first. A plugin marketplace is the end goal and a later enterprise feature; nothing of it is built now.
  • An upstream is a plugin, never the product: no core row, required key, default container or release gate names one upstream. HolmesGPT is harness-holmesgpt and GoAlert is on-call-provider-goalert, both optional.
  • The agent layer is built new: the first-party harness-native, decomposed into small plugins in the DeepSeek Harness manner, with first-party read tools for metrics, logs, traces and Kubernetes.
  • The plugin system follows DeepSeek Harness strictly: 08 section 1.1 lists every dsh property as carried, adapted or not carried.
  • Contributors can add another observability backend as a connector pack. The default stack stays first and is not hard-wired.
  • Licences: no software base forces a rebuild. Compliance content (CIS, SOC 2, ISO text) cannot ship and gets a first-party catalogue; two upstream charts are replaced by our own templates; details in docs/design/licence-audit-2026-11.md.
  • The owner confirmed decisions W2 to W13 on 2026-11-11 (00 section 2.4). Still open: lawyer questions, the community versus enterprise boundary and the contributor agreement. Phase dates are planning targets.
